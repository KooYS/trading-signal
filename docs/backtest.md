# 보조지표 검증

> 2026-09-01. 대상: `signal_round` 10,674 라운드(2014-10 ~ 2026-09).
> 이 문서는 "무엇이 통했나"보다 **"무엇이 안 통했나"**를 남기려고 쓴다.
> 같은 걸 다시 시도하지 않으려고.

## 0. 왜 했나

화면의 진입 점수(수익성·밸류·타이밍·규모 4축)가 실제로 수익률과 상관있는지
아무도 확인한 적이 없었다. 각주에도 "아직 검증하지 않았다"고 적혀 있었다.
목표는 "승률 70% → 80~90%를 만드는 보조지표"였다.

## 1. 방법

**초과수익(alpha)으로 잰다.** 라운드 수익률 그대로 보면 그 달 시장이 뭘 했는지가
결과를 지배한다. 각 라운드의 **실제 보유 창(매수일→매도일)** 에 맞춰 추적 종목
등가중 지수의 같은 기간 수익률을 빼서 비교한다.

```
alpha = profit_rate − (지수(매도일) / 지수(매수일) − 1) × 100
```

지수는 `mkt_index` 뷰(=`price` 등가중 일간수익률의 누적곱). 액면분할·병합으로 튀는
값을 막으려고 일간수익률 ±35% 밖은 버린다.

**미래참조를 피한다.** 모든 지표는 `buy_date` **미만** 데이터로만 계산한다.
결과적으로 실전 제약(09:03 신호 시점에 계산이 끝나 있어야 함)도 자동으로 만족한다.

**일내 랭킹은 따로 잰다.** "이 조건이 평균적으로 좋은가"와 "그날 후보 50개 중
어느 걸 살까"는 다른 문제다. 후자는 같은 날끼리 비교하므로 국면이 상쇄된다.
`그날 평균 대비 초과`로 잰다.

## 2. 신호 자체의 크기

| 연도 | n | 신호 | 시장 | 초과 |
|---|---:|---:|---:|---:|
| 2014~2026 전체 | 6,369 | +1.80% | +1.10% | **+0.71%p** |

**12년 내내 초과수익이 양수다. 한 해도 마이너스가 없다.** 다만 크기가
라운드당 +0.71%p로, 수수료·거래세·슬리피지(왕복 0.3~0.5%p)와 같은 자릿수다.

통산 승률 64.8%의 대부분은 시장이 오른 것이지 신호의 실력이 아니다.

**우위 대비 잡음이 크다.** alpha 표준편차가 14.6%p, 우위가 0.79%p다.
우위가 우연이 아님을 확인하려면 라운드가 **1,400건** 필요하다
(`n = (2×14.6/0.79)²`). 몇십 건 골라 잡아서는 우위가 아니라 운을 잡는다.

| 정배열 | −0.46 | −0.93 | −0.21 | −0.74 |

**10개 지표 전부 "높은 것 1등"이 마이너스다. 예외가 없다.**

반대로 "낮은 것을 고른다"는 t가 0.4~1.5로 전부 무의미했다. **비대칭이다** —
피하는 건 되지만 고르는 건 안 된다. 그래서 화면에서도 감점 방향으로만 쓴다.

**거래량 급증은 해롭다**(−0.78). "거래 터지면 오른다"의 반대다. 라씨 신호가
이미 오르는 것을 잡아주므로, 거기서 더 급등한 것을 고르면 꼭지를 잡는다.

**정배열은 못 믿는다.** 표본·버그 판본에 따라 +0.51 → −0.96 → −0.46 으로 흔들렸다.
과열도 3요소(밴드위치·20일선·매물대)는 세 판본 모두에서 일관되게 음수였다.

## 5-1. 화면 색 규칙

**빨강 = 좋다 / 파랑 = 나쁘다.** 양봉·음봉과 같은 방향이고, 실현수익률이 이미
`+빨강 / −파랑`이라 판단 색을 여기 맞추면 화면 전체가 한 방향으로 읽힌다.

| 요소 | 빨강 | 파랑 |
|---|---|---|
| 과열도 숫자·판정 | 30 이하 "양호" | 70 이상 "과열" |
| 검증된 배지 | IR 공시, 눌림 하위 | 과열 상위 |
| 과열도 막대 | — | 상위 70%↑ 축 |
| 수익률·괴리 | 양수 | 음수 |
| ROE | — | 적자 |

⚠️ 처음엔 과열도 높은 쪽을 빨강으로 칠했다. "많이 올랐다"는 뜻으로는 맞지만
한국 주식 색 감각에서는 "좋다"로 읽혀 정반대가 된다. 색만으로는 방향을 못 읽으니
"양호 / 보통 / 과열"을 말로도 적는다.

## 5-2. 용어 툴팁 — 검증 여부를 용어마다 붙인다

화면의 용어 옆에 `?` 를 달아 눌리면 설명이 뜬다(`GLOSS`, 17개 용어). 설명만
있으면 "정보성으로 띄운 값"과 "검증을 통과한 지표"가 같은 무게로 읽히는 게
문제여서, 항목마다 판정 배지를 같이 넣는다.

- **검증됨**(빨강): 눌림/과열 축, IR 공시. 표본에서 t값이 살아남은 것들.
- **참고용**(회색): 수급, ROE·PER·PBR, 공급계약, 뉴스, 거래량 급증. 검증에서
  무효였고 화면에는 맥락으로만 남긴 것들. 배지가 그걸 명시한다.

즉 §3 의 검증 결과가 문서에만 있지 않고 용어 단위로 화면에 붙어 있다. 나중에
표본이 쌓여 판정이 뒤집히면 `GLOSS` 의 배지도 같이 뒤집어야 한다.

구현에서 막힌 것 세 가지:

1. 힌트 문자열의 `\n` 이 heredoc 을 거치며 실제 줄바꿈이 되어 JS 문자열이 깨졌다.
2. hover 로 연 툴팁을 같은 요소의 click 이 토글로 닫아버렸다(hover+touch 겸용
   기기). `tipMode` 로 "click 이 연 것만 click 이 닫는다"로 갈랐다.
3. 모바일에서 열리자마자 닫혔다. 버튼 클릭 뒤 브라우저가 포커스 스크롤을
   일으키고 그게 `scroll → hideTip` 을 때렸다. 스크롤에는 위치만 다시 잡고,
   기준 버튼이 화면 밖으로 나갔을 때만 닫는다.

- **청산 규칙.** 이길 때 +10.83% / 질 때 −14.44%로 지는 게 더 크다. 손실은
  −10~−15% 구간에 몰려 있다(3,750건 중 2,419건) — 손절 규칙이 있다는 뜻인데
  그게 최적인지 아무도 안 봤다. 일별 시세 12년치가 생겼으니 이제 검증된다.
  **진입 필터가 세 축 다 빈손이었으니 남은 레버는 여기다.**
- 공시 본문(제목만 썼다), 체결 강도, 장중 데이터, 업종·테마 쏠림.

## 7. 검증하다 나온 함정

같은 실수를 반복하지 않으려고 적어둔다.

1. **정수 나눗셈.** `close_price` 가 integer라 `c/c5` 가 정수 나눗셈이 되어
   6900/7275 = 0 → −100%가 나왔다. `ret5`·`ret20`·`vs_hi60` 세 지표가 통째로
   쓰레기였고 그 위에서 낸 결과를 한 번 보고했다가 정정했다. `::numeric` 필수.
2. **PostgREST 1000행 상한.** `limit` 없이 읽으면 조용히 잘린다. `dart_corp`
   3,988행 중 앞부분만 와서 189종목 중 173개가 "DART 미등록"으로 빠졌다.
3. **토스 `table[]` 은 12개 상한.** `{"range":5}` 를 보내도 `table` 은 12분기고
   5년치는 `graph[]` 에 있다. 둘을 period 로 합쳐야 한다.
4. **3개월 표본은 아무것도 말해주지 않는다.** 수급 축이 243건에서는 5%p 격차로
   유망해 보였다가 4,172건에서 사라졌다. t값을 보기 전엔 아무 말도 하지 말 것.
5. **`drop materialized view ... cascade` 는 의존 뷰를 조용히 데려간다.**
   `tech_daily` 를 갈아끼웠더니 `buy_today` → `page_live` 가 함께 지워졌고
   화면이 `/api/data` 404 를 받았다. HTML 배포만 확인하고 API 는 안 봐서
   한참 뒤에야 알았다. **뷰를 갈아끼운 뒤에는 화면이 아니라 API 를 찔러볼 것.**
6. **신규 종목은 당일 지표가 빈다.** 일일 갱신은 08:30 인데 신호는 09:03 에
   나온다. 그때 처음 보는 종목이면 `price` 에 아무것도 없어 과열도가 null 이다.
   `fill_missing_tech()` 를 장중 매시 돌려 메운다.
7. **`flow` 수집 창이 120일이라 밴드가 짧게 그려진다.** `accum_band` 는 365일을
   의도했는데 실제로는 종목당 평균 130거래일, 절반 이상이 100일 미만이었다.
   카카오는 60일치로 그려놓고 화면엔 '1년 매집 분포'처럼 보였다. `flow_backfill`
   로 채운 뒤 평균 238일이 됐다. **밴드에 실제 거래일수를 함께 표시**해 다시
   속지 않게 했다. 신규 편입 종목은 계속 짧게 들어오므로 일일 `backfill`(16:38)이
   `shallow_flow` 뷰를 보고 자동으로 메운다 — 200거래일 미만인 종목 40개씩.
   평소엔 0건이고 신규분만 걸린다.
8. **최신 펀더멘탈을 과거 신호에 붙이면 안 된다.** 타이밍 축이 "현재가 대비
   신호가"인데 현재가가 미래 가격이면 진 종목에 만점을 준다. 상관이 −0.524로
   박히는데 이건 발견이 아니라 계산 착시다. `buy_ranked` 의 as-of 조인이 그래서 있다.

## 8. 재현

DB 객체(전부 `schema.sql` 에 있다):

| 객체 | 용도 |
|---|---|
| `price` | 일별 OHLCV. 189종목, 46만행, 2002~ |
| `tech_daily` (matview) | 이동평균·매물대·밴드위치 등. `price` 에서 파생 |
| `mkt_index` (matview) | 등가중 시장지수. alpha 계산의 기준 |
| `flow_streak_daily` (matview) | 외국인·기관 연속 순매수 일수 |
| `financials` | 분기 매출·순이익·영업이익. 5년 |
| `disclosure` | DART 공시 39,375건, 2019~ |
| `buy_today` | 오늘 후보 + 과열도 + IR |

**matview 는 갱신이 필요하다.** `price` 를 채운 뒤 반드시
`refresh materialized view tech_daily; refresh materialized view mkt_index;`
안 하면 화면이 조용히 옛 지표로 점수를 매긴다.
